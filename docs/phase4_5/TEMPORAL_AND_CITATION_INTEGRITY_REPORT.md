## 1. Dual Temporal Investigation Modes

The ETGNN-Agent platform strictly enforces two distinct temporal investigation modes across the tool registry (`src/agent/tools/investigation_tools.py`), LangGraph workflow (`src/agent/orchestration/nodes.py`), and Graph-RAG retriever (`src/agent/rag/temporal_filter.py`):

### 1.1 `HISTORICAL_EVALUATION` (Point-in-Time Strict Mode)
- **Snapshot Cutoff Enforcement:** When `as_of_snapshot = t_cutoff` is provided, any target transaction or neighbor node with `snapshot_id > t_cutoff` is strictly blocked (`TemporalBoundaryViolationError`), resulting in immediate workflow abstention (`TEMPORAL_LEAKAGE_BLOCKED`).
- **Authoritative Temporal Split:** Consistent with `src/data/create_masks.py` and `data/processed/nodes_with_masks.csv`, the dataset is partitioned into **Train (`snapshots 1–32`)**, **Validation (`snapshots 33–40`)**, and **Test (`snapshots 41–49`)**, with all supervised models trained strictly on snapshots `1–32` (`training_cutoff_step = 32`).
- **Ground-Truth Label Masking:** In `HISTORICAL_EVALUATION` mode, ground-truth class labels (`illicit`, `licit`) for test-split transactions (`split == "test"`, `snapshot_id >= 41`, as well as post-cutoff snapshots when `as_of_snapshot <= 32`) are masked as `LabelStatus.RESTRICTED` (`"restricted_by_policy"`, `raw_label_code = None`) so the agent cannot use future or held-out ground-truth labels as prediction-time evidence.
- **Preservation of Unknown Labels:** Transactions with Elliptic class `"unknown"` (`classLabel = 2` / `-1`) are preserved as `"unknown"` and never coerced into licit or illicit classes.

### 1.2 `RETROSPECTIVE_INVESTIGATION` (Post-Hoc Forensic Audit Mode)
- Permits inspection of historical transactions alongside post-hoc benchmark findings and literature context, while explicitly tagging evidence provenance and preserving point-in-time snapshot boundaries within each snapshot subgraph.

## 2. Citation & Numerical Grounding Verification

Every `ForensicInvestigationReport` generated by the workflow passes through three deterministic verification gates before completion:

1. **`CitationValidator` (`src/agent/validation/citation_validator.py`):**
   - Verifies that every `evidence_id` cited in `supported_findings` exists in the investigation's immutable `provenance_chain`.
   - Verifies that transaction-specific evidence IDs (`EV-TX-...`, `EV-PRED-...`, `EV-SUB-...`, `EV-EXP-...`) match the exact `target_tx_id` of the active investigation (preventing cross-transaction citation contamination).
2. **`ClaimValidator` (`src/agent/validation/claim_validator.py`):**
   - **Metric-Specific Numerical Tolerances:** Model probabilities asserted in text must match the source `EvidenceRecord` within `±0.01` (`PROBABILITY_TOLERANCE = 0.01`), and benchmark metrics (AUPRC/F1) within `±0.001`.
   - **Exact Degree Verification:** Asserted `in-degree` and `out-degree` counts must match the exact integer values in `TransactionEvidence`.
   - **Prohibited Hallucinations & Overclaims:** Rejects invented feature names (`wallet_age`, `gas_fee`, `mixer_fee`, `ip_address`), judicial guilt claims (`proves guilt`, `confirmed money launderer`), and unverified darknet causal claims (`snapshot 43 was caused by silk road`, `darknet shutdown caused`).
3. **`ReportValidator` (`src/agent/validation/report_validator.py`):**
   - Automatically degrades any unsupported or unverified claim from `supported_findings` into `uncertain_findings` with the exact rejection reason appended.
   - Injects mandatory Snapshot 43 and topological degree qualifications into `limitations`.
